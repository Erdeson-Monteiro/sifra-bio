# Sifra Bio · Protótipo para o pitch  Especificação do protótipo da Sifra Bio para o 2º Hackathon StartUB (Sebrae + Unibalsas, Balsas-MA). Leia o arquivo inteiro antes de começar e siga as etapas da seção 12 na ordem. Tudo o que aparece para o usuário é em português do Brasil.  ## Como usar este arquivo  1. Crie um repositório vazio no GitHub chamado `sifra-bio` e coloque este arquivo na raiz, com o nome `CLAUDE.md`. 2. Abra o projeto no Claude Code. 3. Cole este pedido:  > Leia o CLAUDE.md inteiro. Construa o protótipo Sifra Bio seguindo as etapas da seção 12, na ordem. Ao fim de cada etapa, rode o projeto, confira o critério da etapa e faça um commit. Use só as dependências da seção 2. Quando terminar a etapa 7, me diga o passo a passo para publicar no Easypanel.  Tempo estimado: de 4 a 5 horas.  ---  ## 1. O que estamos construindo  A Sifra Bio é um agente de vendas no WhatsApp para extrativistas e agricultores familiares do Sul do Maranhão. A produtora manda um áudio, e a Sifra responde o preço, registra a venda, confere os papéis (CAF, nota fiscal) e gera um QR com a origem do lote. A associação acompanha tudo num painel. O comprador ou a escola lê o QR e vê de onde veio o produto e quanto a produtora recebeu. Uma empresa do agro "adota" a comunidade e acompanha o impacto.  Este protótipo **não** se conecta ao WhatsApp de verdade. Ele **simula** a conversa com dados fictícios, mas tem servidor e banco reais, para que:  - uma venda feita na tela do WhatsApp apareça **na hora** no painel, em qualquer aparelho; - o QR do lote funcione de verdade: a banca escaneia com o celular e abre a página do lote.  ### A demonstração no pitch (cerca de 30 segundos)  1. Abrir a tela de entrada e mostrar os 3 caminhos. 2. Entrar como produtora, ir para o WhatsApp e clicar em "Rodar demonstração". A conversa acontece sozinha em uns 20 segundos e termina com "Venda registrada" e o QR. 3. Trocar para o painel: a venda da Maria aparece no topo, com o aviso de nova venda. 4. Mostrar o QR do lote para a banca escanear, ou abrir a página do lote.  ---  ## 2. Stack (simples, tudo num container só)  | Parte | Escolha | Por quê | |---|---|---| | Servidor | Node.js 22 LTS + Express 5 | Uma linguagem só (JavaScript) no servidor e no navegador | | Banco | SQLite com `better-sqlite3` (arquivo `data/sifra.db`) | O banco roda dentro do mesmo processo e do mesmo container, sem serviço separado | | Telas | HTML + CSS + JavaScript puro em `public/`, servidos pelo Express | Sem etapa de build e sem framework | | Tempo real | Server-Sent Events (`EventSource` no navegador) | O painel atualiza sozinho quando entra uma venda | | QR code | Pacote `qrcode`, gerando SVG no servidor | QR real, que abre a página do lote | | Container | Um `Dockerfile` com `node:22-slim` | Sobe igual no notebook e na nuvem | | Hospedagem | Easypanel no nosso servidor (VPS), deploy pelo GitHub usando o Dockerfile | Não dorme, tem domínio próprio e guarda o banco num volume |  Dependências permitidas: `express`, `better-sqlite3` e `qrcode`. Não adicionar ORM, framework de front, bundler nem banco separado.  ---  ## 3. Banco de dados (SQLite)  ```sql CREATE TABLE IF NOT EXISTS familias (   id INTEGER PRIMARY KEY,   nome TEXT NOT NULL,   comunidade TEXT NOT NULL,   municipio TEXT NOT NULL,   mulher INTEGER NOT NULL,          -- 1 = mulher   caf TEXT NOT NULL,                -- 'ativo' | 'vence_em_breve' | 'vencido' | 'sem'   cpf_ok INTEGER NOT NULL,   sican_ok INTEGER NOT NULL,   pix_ok INTEGER NOT NULL );  CREATE TABLE IF NOT EXISTS vendas (   id INTEGER PRIMARY KEY,   lote TEXT UNIQUE NOT NULL,        -- ex.: 'BAC-0042'   familia_id INTEGER NOT NULL REFERENCES familias(id),   produto TEXT NOT NULL,            -- slug da tabela regras   kg REAL NOT NULL,   preco_kg REAL NOT NULL,   valor REAL NOT NULL,   comprador TEXT NOT NULL,   canal TEXT NOT NULL,              -- 'merenda' | 'cooperativa' | 'atravessador' | 'feira'   nota TEXT NOT NULL,               -- 'emitida' | 'pendente'   nota_numero TEXT,   subvencao REAL NOT NULL DEFAULT 0,   criado_em TEXT NOT NULL           -- ISO 8601 );  CREATE TABLE IF NOT EXISTS pendencias (   id INTEGER PRIMARY KEY,   familia_id INTEGER NOT NULL REFERENCES familias(id),   tipo TEXT NOT NULL,               -- 'nota' | 'caf' | 'sican' | 'pix' | 'documento'   descricao TEXT NOT NULL,   avisado INTEGER NOT NULL DEFAULT 0 );  CREATE TABLE IF NOT EXISTS regras (   id INTEGER PRIMARY KEY,   slug TEXT NOT NULL,               -- 'babacu' | 'bacuri' | 'buriti' | 'farinha' | 'feijao'   produto TEXT NOT NULL,   prefixo_lote TEXT NOT NULL,   vigencia INTEGER NOT NULL,        -- 2026 | 2027   preco_referencia REAL NOT NULL,   fonte_preco TEXT NOT NULL,   preco_minimo REAL,                -- NULL = sem preço mínimo da Conab   subvencao_kg REAL,                -- NULL = não se aplica ou ainda não publicada   observacao TEXT );  CREATE TABLE IF NOT EXISTS config (chave TEXT PRIMARY KEY, valor TEXT); ```  - O arquivo do banco fica em `process.env.DB_PATH` (padrão `./data/sifra.db`). Criar a pasta se não existir. - Ao iniciar: criar as tabelas e, se `familias` estiver vazia, rodar o seed. - `POST /api/reset` apaga tudo e roda o seed de novo. - O número do lote é o prefixo do produto mais uma sequência global de 4 dígitos (a próxima venda depois do seed é `0042`).  ---  ## 6. Telas  Todas as páginas internas têm uma barra no topo com "Sifra Bio", os links Início · WhatsApp · Painel · Lote (e Regras, se existir) e o selo "Protótipo · dados simulados".  ### 7.1 Entrada (`/`)  Parece uma tela de login, mas não pede senha. Duas colunas, que viram uma no celular.  - **Esquerda (fundo verde):** "Sifra Bio", a frase "O agente de vendas de quem colhe e de quem planta." e três linhas curtas: "Responde o preço", "Confere os papéis", "Prova a origem". - **Direita (cartão claro):** título "Entrar na Sifra", subtítulo "Escolha como você usa a Sifra" e três botões grandes, cada um com um ícone simples, um título e uma linha:   1. **Sou produtora ou produtor**: "Converse com a Sifra pelo WhatsApp" → `/whatsapp`   2. **Sou associação ou cooperativa**: "Vendas, papéis e impacto num painel" → `/painel`   3. **Sou comprador ou escola**: "Leia o QR e veja de onde veio o lote" → `/lote` (abre o lote mais recente) - Link pequeno embaixo: "É empresa do agro? Ver o painel de impacto" → `/painel#impacto`. - Rodapé: "Protótipo · dados simulados · 2º Hackathon StartUB" e um botão discreto "Reiniciar demonstração". Ele pede confirmação na própria página (sem `confirm()`) e chama `POST /api/reset`.  ### 7.2 WhatsApp simulado (`/whatsapp`)  - **No computador:** um celular desenhado (cerca de 400 px de largura e até 85% da altura da tela) e, ao lado, o painel "O que a Sifra está fazendo" com os controles. - **No celular:** o chat ocupa a largura toda, e o painel e os controles ficam embaixo.  **Chat**  - Cabeçalho verde com uma bolinha amarela (avatar), "Sifra", "online" e, à direita, "WhatsApp (simulação)". - Fundo `--chat-fundo`. Balões da produtora à direita (`--balao-dela`) e da Sifra à esquerda (`--balao-sifra`), cada um com a hora atual. - Antes de cada resposta da Sifra, "Sifra está digitando…" com três pontinhos, por 0,8 a 1,2 segundo. - **Balão de áudio:** botão de play (só visual), ondas desenhadas em CSS, a duração ("0:08") e, embaixo, "Transcrição: …" em itálico. - **Balão de anexo:** ícone de documento e o nome "nota-fiscal-bacuri.pdf". - A área do chat tem `aria-live="polite"`.  **Roteiro do botão "Rodar demonstração"** (uns 20 segundos, uma mensagem a cada 2,5 segundos)  1. Maria (áudio 0:08): "Sifra, quanto tá o quilo da polpa de bacuri?" 2. Sifra: "Oi, Dona Maria! Hoje a Cooperativa de Polpas do Cerrado paga R$ 38,00 o quilo e entrega para a merenda da escola. Quer vender para ela?" (o valor e o comprador vêm de `GET /api/perguntar?produto=bacuri`) 3. Maria (áudio 0:04): "Quero. Tenho 20 quilos." 4. Sifra: "Conferi seus papéis: CAF ativo, CPF e Pix em dia. Falta só a nota fiscal desta venda. Te guio agora: 20 kg × R$ 38,00 = R$ 760,00." 5. Maria (anexo): "nota-fiscal-bacuri.pdf" e o texto "Pronto, tirei." 6. Sifra: cartão "Venda registrada" com lote, produto, kg, valor, um QR pequeno e o botão "Abrir página do lote". Neste passo o navegador chama `POST /api/vendas` (`{ familia: "Maria", produto: "bacuri", kg: 20, canal: "merenda", nota: "emitida", comprador: "Cooperativa de Polpas do Cerrado (exemplo)" }`) e usa o lote que o servidor devolver. 7. Sifra: "Avisei a associação. Quando a cooperativa pagar, te mando o comprovante."  **Painel "O que a Sifra está fazendo"**  Quatro passos que acendem conforme a conversa avança:  - **Responde**: preço e comprador (mensagens 1 e 2) - **Confere**: CAF, CPF, Pix e nota (mensagens 4 e 5) - **Registra**: a venda entra no painel da associação (mensagem 6) - **Prova**: QR com a origem e o preço pago (mensagens 6 e 7)  **Controles**  - "▶ Rodar demonstração": roda o roteiro inteiro. - "Próxima mensagem": avança uma mensagem por vez (a tecla espaço faz o mesmo). - "Recomeçar conversa". - Perguntas rápidas, em botões que acrescentam a pergunta e a resposta no chat:   - "Quanto tá o babaçu?" → `GET /api/perguntar?produto=babacu`   - "Que papéis eu preciso para vender para a merenda?" → resposta fixa (seção 8)   - "Quem tá comprando bacuri?" → `GET /api/perguntar?produto=bacuri`  ### 7.3 Painel da associação (`/painel`)  - **Cabeçalho:** nome da associação, "Balsas (MA)" e o interruptor "Simulação ao vivo". - **Faixa de números** (6 blocos, de `GET /api/resumo`): Famílias (30) · Papéis em dia (21 de 30) · Vendido no mês (R$) · Vendas no mês · Lotes com QR · Subvenção a pedir (R$). Ao clicar, o botão vira "Aviso enviado (simulado)". - **Aba Impacto** (para a empresa do agro):   - Topo: "Comunidade adotada pela Fazenda Parceira (exemplo) há 5 meses".   - Números: renda registrada desde a adoção, famílias atendidas, mulheres (22 de 30), kg com origem registrada, vendas para a merenda e subvenção destravada.   - Gráfico de barras simples, em SVG ou CSS e sem biblioteca, com a renda por mês.   - Frase fixa: "A empresa vê os números do território, não os dados pessoais das famílias." - **Tempo real:** a página atualiza sozinha pelo SSE (`/api/eventos`), sem recarregar.  ### 7.4 Página do lote (`/lote/:codigo`; `/lote` abre o mais recente)  É o que o comprador e a escola veem ao ler o QR, então precisa ficar ótima no celular.  - **Topo:** "Lote BAC-0042", a etiqueta "Verificado pela Sifra" e o selo de dados simulados. - **Produto:** "Polpa de bacuri · 20 kg". - **Quem colheu:** "Maria", "Agricultora familiar e extrativista", comunidade e município. - **Preço pago à produtora (em destaque):** "R$ 38,00 por kg · total R$ 760,00". - **Comprador e destino:** "Cooperativa de Polpas do Cerrado (exemplo) → merenda da Escola Municipal (exemplo)". - **Documentos:** CAF ativo, nota fiscal (com o número) e venda registrada, ou "Nota pendente". - **Linha do tempo:** Coleta → Venda registrada → Nota emitida → Entregue → Merenda, com datas. - **QR grande** (`GET /api/lotes/:codigo/qr.svg`), apontando para o endereço público desta página. Se a nota estiver pendente, no lugar do QR aparece: "O QR sai quando os papéis estiverem em dia." - **Rodapé:** "Demonstração com nomes e números fictícios. Sifra Bio · 2º Hackathon StartUB."  ### 7.5 Tabela de regras (`/regras`, etapa opcional)  - Mostra as regras da vigência ativa. - Seletor "Vigência: 2026 | 2027" (`POST /api/regras/vigencia`). - Preço de referência editável (`PUT /api/regras/:id`). - Frase: "A Sifra responde a partir desta tabela. Mudou a regra? Muda aqui, sem mexer no código." - **Teste da demonstração:** trocar para 2027 e perguntar "Quanto tá o babaçu?" no WhatsApp. A resposta passa a dizer R$ 9,15 e que o valor da subvenção de 2027 ainda não foi publicado.  ---  ## 8. Respostas da Sifra (`src/respostas.js`)  As respostas são montadas a partir da tabela `regras` na vigência ativa, com valores no formato brasileiro (R$ 1.234,56).  - **Produto com preço mínimo (babaçu):**   "Amêndoa de babaçu: o preço mínimo da Conab em {vigência} é R$ {mínimo} por kg. No Maranhão, o preço pago foi de R$ {referência} por kg ({fonte}). Se vender abaixo do mínimo, com nota e CAF, você pode pedir R$ {subvenção} por kg de subvenção."
